Item 8: the refresh wiring - weekly task, in-process bracket, run sheet

The bracket is in-process rather than stop/start, and the handover wording
changes with it: the portal is a console process launched by Meridian-run.bat,
not a Windows service, so a scheduled task cannot restart it cleanly. What the
DuckDB single-writer rule actually requires is that the portal holds no store
connections while the loader writes, and that the first query afterwards
re-opens against the new file handles.

  the gate's new step 3 refuses /api with an honest 503 while paused),
  POST /api/refresh/end (reset again so nothing re-opened mid-window survives
  on old handles, then resume; closes the 6 July S16 item), GET
  /api/refresh/state. Both POSTs answer to the existing origin gate; the
  wrapper authenticates with QSI_PASSWORD over Basic auth.

THE SAME-DAY PACK (critical path 2A, controller rulings 26 September)

app/pack_queue.py, new, on the same DuckDB store as the lead record. The lead is the person and
exists from the moment the host captures it; the job is one pack for one run. Three states, as
ruled: NOW sends on the build's own checks, HOLD (default) waits the configured hold and sends
itself, PAUSED waits for a person and states why.

Two properties are held by tests rather than by intention:

  a build that fails any check goes to PAUSED and never to send. There is no code path from a
  failed check to a delivered pack, and the test asserts it for a job a day past its clock;

  a send is not recorded without the provider's own message id. The 21 September SMTP discard is
  the reason.

The hold is a SETTING in minutes, stored, changed on the queue page with no restart, read when
each build passes. Zero means send on pass and is held apart from unset. A paused job appears once
on the holding-email list so the visitor is told the same day, and once only.

  app/pack_queue.py           the store, the states, the settings, the event log
  app/test_pack_queue.py      60 checks, 0 failed
  app/cortex_app.py           /api/pack/request|list|job|action|hold|preview and /demo/queue
  app/cortex_dashboard.html   the email field at the foot of the run, on Run and Optimise

The queue view is newest first, one line a job with the countdown visible, two actions, and a
preview button that appears once a build has written a file. Built to be read on a phone.

Not done and next: W3's generator called from the queue, and the sender. Nothing leaves yet.

NO ECONOMICS FIGURE UNTIL PRE-MORTEM 33 CLOSES

Three surfaces were showing one: the Economics navigation entry and the page behind it, the
"+ Economics" output button, and #econRow on the result page, whose headline states an annual
contribution and whose table states revenue. All three are now withheld behind
AVIA_SHOW_ECONOMICS, default off. The elements are removed rather than hidden, /economics returns
a short page saying the view is withheld while the cost basis is checked, and the server states
which way the switch is set on every start. The Optimise contribution ranking is ordinal and is
untouched.

TWO PRESENTATION SLIPS (John, TIF-AUH, 27 September)

"incl. feed" now prints only when the connecting figure is above zero.

The rotation diagram drew seven days for a 3x schedule. Not a drawing fault: drawTail read
d.capacity.frequency and the payload's key is cap.freq, so every branch fell through to a literal
7 and an Optimise result at 3x, where the visitor has typed no frequency, silently drew a daily
rotation and printed "Pattern basis: daily". Fixed to the right key, and where no frequency can be
established the diagram is withheld rather than drawn on an assumed one. Same shape as the MCT and
friction faults: a lookup that misses, a neutral default substituted in silence.

THE FRICTION RASTER, ON A NEW WORKSTATION

The launcher sets AVIA_DRIVE_TIMES=1 and echoes "road drive times on", but nothing in it points at
the raster, and config resolved it from the cache and the Egnyte root, neither of which holds it.
config.FRICTION_RASTER now resolves from AVIA_ROOT first, the variable the launcher sets and the
one a cloned product drive carries, so road times work on a new machine with nothing set by hand.
Whether AVIA_FRICTION is currently set at machine scope on donatello is unconfirmed; the startup
line answers it on the next restart and the runbook makes it a stop condition.
